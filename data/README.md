# data/

This directory holds the input artifacts for the HumanEval+ pilot
experiment (Phase 8). Nothing here is fabricated or copied from the
paper's (unavailable) replication package — everything was generated
during this reproduction and is kept for full traceability.

## Contents

- `pilot_humaneval_tasks.json` — 21 HumanEval task prompts and reference
  (`canonical_solution`) implementations, generated by
  `scripts/prepare_humaneval_tasks.py` from the `human-eval` PyPI
  package's bundled `HumanEval.jsonl.gz` (see `report/report.md` Section 4
  for why HumanEval, not HumanEval+'s stronger test suite, is used as
  ground truth). 20 of these 21 tasks make up the final Haiku-based
  manifest in `scripts/run_experiment.py`; the 21st (`HumanEval/8`,
  `sum_product`) is kept from an earlier Sonnet-only exploratory round
  (`EXPERIMENT_LOG.md` Entries 6-7) for a complete record, even though it
  is not part of the final reported Table IV row. The
  `canonical_solution` field is used only internally as ground truth for
  fault classification — it was never shown to any candidate- or
  test-generation subagent.

- `pilot_generation/` — raw outputs from the generation subagents, saved
  verbatim, one pair of files per task:
  - `<entry_point>_candidates_v3_haiku.txt` — 5 candidate implementations
    generated by Claude Haiku 4.5, blind to the reference solution, parsed
    by `src/humaneval_pilot.parse_candidates`.
  - `<entry_point>_tests.json` — 10-15 structured `{args, expected_output}`
    test cases generated blind (from the task prompt only), parsed by
    `src/humaneval_pilot.parse_test_pool`.
  - Files suffixed `_v2_underspecified` or `_v3_haiku` for the first 5
    tasks reflect the exploratory rounds described in `EXPERIMENT_LOG.md`
    (Entries 6-9) — kept for transparency rather than deleted, since a
    research reproduction should show failed attempts, not just the final
    one. `scripts/run_experiment.py`'s `TASK_MANIFEST` records exactly
    which file is authoritative for each task's final result.

## Provenance summary

See `EXPERIMENT_LOG.md` for the full, timestamped account of how this data
was produced, including the null results (0/45 candidates faulty using
Claude Sonnet, both with original and deliberately under-specified
prompts) that motivated switching to Claude Haiku 4.5 as a weaker
substitute fault-generating model.
